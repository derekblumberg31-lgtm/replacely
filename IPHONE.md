# Running Replacely on an iPhone

Replacely is a mobile-first PWA. You can open it in iPhone Safari over your local Wi-Fi, or install it to
the Home Screen so it behaves like a small native app. No Apple Developer account, Xcode project or App
Store review is involved.

There are two levels of “installed”:

| Setup | Home Screen icon | Full screen | Works without the Mac | Works with no internet |
| --- | --- | --- | --- | --- |
| `http://192.168.x.x:5180` over Wi-Fi | Yes (web clip) | Yes | No — needs the Mac server | No |
| The built app on an HTTPS address | Yes (PWA) | Yes | Yes | Yes, after the first load |

iOS only permits service workers — the technology that caches a web app for offline use — in a **secure
context**. `localhost` counts as secure on the Mac, but `http://192.168.x.x` does not count on the
iPhone. That is a Safari rule, not a Replacely setting.

## What you need

- **Mac** with macOS and a Wi-Fi connection.
- **Node.js 20.19+ or 22.12+** and npm. Check with `node -v` and `npm -v`.
- **iPhone** on the same Wi-Fi network, with Safari.
- No environment variables, API keys or accounts. The app has no backend.

For offline installation you also need an **HTTPS address**. The easiest reliable route is a free static
host (see [Offline use after installation](#offline-use-after-installation)); no Mac is needed after the
first load.

## 1. Start the app on the Mac

From the project folder:

```bash
npm install
npm run dev:iphone
```

`dev:iphone` binds Vite to all network interfaces on port **5180**. The terminal prints:

```text
Local:   http://localhost:5180/
Network: http://192.168.1.42:5180/
QR code for the network URL
```

The QR code is generated automatically at startup. If port 5180 is already in use, Vite chooses the next
free port; use the URL and QR that it actually prints.

> `npm run dev` does the same thing (the host is enabled in `vite.config.ts`). `dev:iphone` is just an
> explicit, memorable command.

### Find the Mac's local address manually

The terminal usually picks the right Wi-Fi interface. If it prints a VPN or Docker address instead, run:

```bash
ipconfig getifaddr en0
```

If that returns nothing, try `en1`. On newer Macs, Wi-Fi is normally `en0`. The URL is then:

```text
http://<that-address>:5180/
```

Do **not** type `localhost` or `127.0.0.1` into the iPhone — those point at the iPhone itself.

## 2. Open and install it on the iPhone

1. Connect the iPhone to the **same Wi-Fi** as the Mac.
2. Open the iPhone **Camera**, point it at the QR code in the terminal, and tap the banner that appears.
   Or type the `http://192.168.x.x:5180/` address into **Safari**.
3. Wait for Replacely to load. If it is your first visit, the four-page guide appears; swipe through it.
4. Tap the **Share** button (square with an arrow) in Safari's toolbar.
5. Scroll down and tap **Add to Home Screen**.
6. Keep the name **Replacely** and tap **Add**.
7. Open Replacely from the Home Screen. It runs without Safari's toolbars, with the notch and home
   indicator respected.

To remove it later, touch and hold the Home Screen icon and choose **Remove Bookmark** / **Delete**.
Removing the icon can remove its website data, so export a backup first.

### Install from the iPhone, with no Mac

If you host the production build on HTTPS, the steps are the same, except the URL is the HTTPS one. The
Home Screen app caches itself on first open and then works with the Mac off and no internet.

## 3. Development vs. production

- `npm run dev:iphone` is for active development: instant updates, no service worker, needs the Mac.
- `npm run build` type-checks and writes the production app to `dist/`.
- `npm run preview:iphone` serves that production build on the LAN. This is the build that registers the
  service worker, but over plain LAN HTTP Safari still will not allow it. Use HTTPS (below) for offline.

Icons are generated from `public/icons/app-icon.svg` by `npm run icons`. The manifest and service worker
are generated by Vite at build time.

## Offline use after installation

### Option A — a free HTTPS static host (recommended)

This is the reliable way to get a real, offline-capable Home Screen app.

1. On the Mac:

   ```bash
   npm run build
   ```

2. Upload the **contents of the `dist/` folder** to any static host that serves HTTPS. For example:
   - **Netlify Drop**: open <https://app.netlify.com/drop>, drag the `dist` folder in, and copy the
     `https://…netlify.app` URL.
   - **Cloudflare Pages**: create a project, choose direct upload, and upload `dist`.

   Serve the app from a domain root so its absolute icon and manifest paths resolve normally.
3. Open the HTTPS URL in **Safari on the iPhone**. Let it finish loading once.
4. Tap **Share → Add to Home Screen → Add**.
5. Open Replacely once from the Home Screen while online, then test it in Airplane Mode. The app shell and
   icons come from the cache; your filters come from the phone's local storage.

No Mac is needed after step 5, and no internet is needed to open the app or edit filters.

> A static host publishes the app publicly. Replacely has no server or secrets, but the URL is public. If
> you need a private install, use a host with access protection, or a temporary tunnel.

### Option B — a temporary HTTPS tunnel (advanced)

If you have [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)
installed, you can expose the local preview through a temporary HTTPS URL:

```bash
npm run build
npm run preview:iphone
# in a second terminal:
cloudflared tunnel --url http://127.0.0.1:5180
```

Open the printed `https://…trycloudflare.com` URL in iPhone Safari, add it to the Home Screen, and open it
once while the tunnel is running. After it has cached, it continues to open offline even when the tunnel
and the Mac are gone. Quick tunnels are temporary and their URLs change; use a permanent HTTPS host if
you want a durable install and future updates.

## Using Replacely on the phone

- **Tabs** — Filters, Schedule, Insights and Settings. A red badge on Filters means something is overdue;
  an orange dot means something is due soon.
- **Swipe a filter card left** to reveal **Replace**, or use the Replace button on the card. Replacing
  starts a new countdown and logs the previous filter's run.
- **Tap a card** for details, notes, cost and replacement history. Use **Edit** in the sheet header.
- **Pull a sheet down** by its grabber to close it (or tap outside it). Swipe left/right in the tutorial.
- **Settings → Theme** switches between System, Light and Dark.
- **Settings → Your data** exports a JSON backup. Import replaces the filters on that device; the app asks
  before overwriting.

The first-run guide appears once. Replay it from **Settings → Help → How Replacely works** or from the
empty Filters screen.

## Environment variables

None. There is nothing to configure in `.env` and no secrets are needed. The app is entirely client-side.

## Troubleshooting

### Safari says it cannot connect

- Confirm both devices are on the **same Wi-Fi** and not on a guest network. Guest networks often block
  device-to-device traffic.
- Turn off **VPN / Private Relay** on the iPhone and any VPN on the Mac for the test.
- Use the Mac's Wi-Fi IP (`ipconfig getifaddr en0`), not `localhost`, and include the port: `:5180`.
- On macOS, allow incoming connections for **node** when prompted. If you dismissed the prompt, check
  **System Settings → Network → Firewall → Options** and allow Node.
- A wrong QR URL usually means Vite picked a VPN or Docker interface. Scan again after printing the Wi-Fi
  address directly, or type `http://<wifi-ip>:5180/` manually.
- Make sure the terminal still shows the server running. Closing the terminal stops it.

### The QR code does not scan

Terminal QR codes render differently in different fonts. Open the `Network` URL in Safari manually, or
use a QR generator on another device. The link is just the HTTP URL.

### “Add to Home Screen” is missing

Use **Safari**, not Chrome, Firefox or an in-app browser (for example the Instagram or Gmail browser).
It is also unavailable in some private-browsing states; open a normal tab.

### There is no Home Screen icon, but the app works

That is a web clip rather than an installed PWA. It still opens full screen and keeps data on the phone,
but it needs the Mac server each time. Follow the HTTPS route for an offline-capable install.

### It does not work in Airplane Mode

- Plain `http://192.168.x.x` cannot work offline; iOS only caches service workers on HTTPS. See
  [Offline use after installation](#offline-use-after-installation).
- Make sure you opened the **HTTPS production build**, not `npm run dev`. The service worker is disabled
  in development.
- The first visit must complete online so the app can cache. Open it from the Home Screen once while
  online, then try again.
- If a host changes its URL, it is a new origin with a new cache. Reinstall from the current HTTPS URL.

### An old version is still showing

The service worker is configured to update automatically. Close and reopen the Home Screen app while
online. If it stays stale, delete the Home Screen icon, clear that site's website data in
**Settings → Safari → Advanced → Website Data**, and reinstall from HTTPS. Export a backup first if the
filters matter.

### My filters disappeared

Data is stored per origin. `http://192.168.x.x:5180`, `http://localhost:5180` and an `https://…` deployment
are three separate stores. Open the exact origin you used before. If Safari data was cleared, reinstall
or import the JSON backup. Exporting a backup is the only backup mechanism.

### Removing the app removed my data

iOS may remove website data when a Home Screen web app is deleted. Always export a backup first. Import it
from **Settings → Your data → Import backup**.

### Notifications do not appear

iOS web apps cannot schedule local notifications. Replacely shows a red overdue badge and an orange due
dot on the Filters tab instead; all countdowns work. On desktop browsers, optional reminders appear when
the app is opened, at most once a day, and need notification permission plus a secure context.

### The countdown looks off

Dates are local calendar dates, and the countdown uses the iPhone's clock. Check the date, time zone and
automatic time setting on the phone. Install dates cannot be in the future, and a replacement cannot be
dated before the current filter was installed.

### Text or buttons feel too large / small

Replacely uses the iOS system font and respects Dynamic Type where Safari allows. If the layout feels
crowded at a very large text size, reduce the text size in **Settings → Accessibility → Display & Text
Size**, or use landscape on a larger phone.

## Why a PWA instead of React Native?

For this app, the PWA is the smaller, more practical route: one codebase, no Xcode or Expo Go, no native
build or signing, and installation directly from Safari. It supports the full-screen app experience,
gestures, sheets, dark mode, local storage and offline caching. A native build would only add value for
background push notifications or App Store distribution; iOS web apps cannot schedule those local alerts,
but Replacely's countdowns and due badges do not require them.
